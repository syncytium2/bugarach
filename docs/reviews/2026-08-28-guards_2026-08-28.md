# Murderboard run — the guards briefing (`docs/handoffs/2026-08-28-guards.md`)

## What was at stake

A session is about to be spun off onto guard cells, and the guard record in this tree
**reverses itself twice**. `a15f5e3` is titled *"the prediction held"*; `forks.md` §4a,
written three days later, is titled *"the prediction did **not** hold"*; `27e6c8f` says
§4a's conclusion is false in the tail. All three are on `main`, none is marked stale, and
the ruling that governs whether any of the work may start **is not on `main` at all** —
it lives on `cfar-is-a-knob-axis`, PR #304, open and unmerged since 2026-08-26.

So the deliverable's whole job is to be **quotable without being wrong**, and this review's
job was to check every quote. Nothing in the page is new measurement; the failure mode
available to it is not a bad experiment, it is a **stale or miscounted citation** — which
is precisely the defect class the last four days in this repo have been made of.

Four survived the draft. Two of them were counts of the repo's own contents.

## What the roles found

**The draft claimed a rule that does not exist.** It said four of the seven probes carry a
`--selftest` "and they are the four written after the lesson" — a tidy causal story, and
false: `probe_real_crowding.py` was written for #319, *after* all four, and has none.
There are also **eight** probes, not seven; the table had two tools sharing one row. A
reader acting on the story would have assumed any probe written from here on inherits the
guard, which is the opposite of what the page should teach. It now states the split, says
it is **not** chronological, and names the four files that still need one.

**Two counts of the tree were wrong in the opening paragraph** — the place a reader trusts
most and checks least. "Four figures" against five on disk; "six probes" against eight
tools. The figure count is now five and the probe count is scoped to the six
`probe_guard_*` tools it actually meant.

**A claim about the site was true and unverifiable.** *"The four pages `build_site.py`
serves carry no number measured with a guard on"* requires knowing what every served page
was built from. The mechanism is both stronger and checkable: `guard_sec` defaults to
`0.0` and **no operating point sets it**, so nothing outside the probes and the three test
files that exercise it has ever run with one on. Restated that way — and the blind pass
then caught that "two tests" was itself wrong, because `test_rate_detect.py` sets a guard
too and the inventory had omitted it entirely.

**And "crowding" carried a number before it had a definition** — the same finding the
2026-08-27 handoff review made about the handoff it reviewed, recurring in the page
written a day later. It is defined at first use now, along with self- and mutual masking,
and the three simulated recordings that the rest of the page names constantly.

## How it generalises

The page's own argument is that a record can be true at every point and misleading as a
whole, because nothing marks which of three contradicting documents is current. This
review found the same shape one level up: the draft's **story about its own probes** was
false in exactly the way §4a's story about its own mechanism was false — a plausible
causal account laid over a real observation, where the observation was right and the
account was invented. Both were caught by counting rather than by reading.

The cheapest check in this run was `ls tools/ | grep guard | wc -l`.

### Residual ⚠

1. **Single-pass, not parallel arms.** This session is configured not to spawn agents, so
   the eleven roles were walked in turn by one reviewer. The process names role 2 as the
   one the size rule may never collapse — but only for deliverables that **attribute a
   method or claim novelty**, and this one cites no external literature and claims nothing
   as ours. The attribution risk it carries is inherited from
   `guard_prior_art_2026-08-26.md`, which is flagged in the page as not murderboarded and
   abstract-only. That flag is the residual, not this page's citations.
2. **Four probes still have no `--selftest`.** Named in the page as unclaimed work.
   Nothing here fixes it.
3. ~~**The deferral's home file is not on `main`.**~~ **Retired the same day, and the
   answer was that nothing was wrong with the PR.** This review reported it as a residual
   because the page had to work around it with a `git show`. Asked *"how is 304 not
   merged?"*, the answer turned out to be **nothing** — `mergeable: true`,
   `mergeable_state: clean`, three checks green since 2026-08-26T02:16Z, no review
   required, and **auto-merge never armed**. It had been sitting for two days because
   nothing in this repo merges a PR by itself. Tony merged it; the page now links the
   ruling, and this run record's own workaround paragraph is gone with it.

   ⚠ **The finding underneath it is not retired**, and it is larger than one PR: at the
   time of this review **five of seven green PRs had no auto-merge armed** (#304, #292,
   #360, #53, #50), against a CLAUDE.md rule that says to arm it when the PR is opened.
   #270 was the only one blocked by anything technical. A PR that is green and unarmed is
   indistinguishable from one that is waiting on a decision, which is how a ruling stayed
   off `main` for two days while three sessions wrote around its absence.
