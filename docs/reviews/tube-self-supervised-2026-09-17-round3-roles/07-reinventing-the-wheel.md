## Checked and matching (no finding)
* The truth-reading threshold calls `bugarach.learn.train.pick_threshold` itself (logit mode, quantile grid, `report=`), with `fold_maker`'s `n_val` and `merge_gap_frames=20`, the same as the bake-off.
* The supervised arm's `train()` call is identical to `tools/fair_bakeoff.py:293`. The generator (`fb._make_recording`, `generator_spec.json["generator"]`, `grid_sec` 0.1) matches `train`'s default `dt`.
* Loading goes through `look_rigid_shift.load` → `bugarach.io.load_folder` → `surrogate_stats.recordings_from_slices`, i.e. the export folder, with no filter added. Mouse folds come from `surrogate_discriminator.mouse_folds`, twins from `look_rigid_shift_controls.twin_pair` and `surrogate_stats.destruction_twins`, and hand-written detectors from `detect_folder.detect_slice`.
* The dither control in `look_rigid_shift_controls.py` goes through `bugarach.surrogates` (`uniform_dither`).
* The summary tool's zero-fill for undefined F1 does not change the bake-off: no fold in the three `bakeoff_seed*` files has an undefined F1. In the training run, 316 of 1,500 score cells are undefined, and the README says they score 0.
* Could `np.convolve(mode="same")` misalign the 128-frame kernel (6,145 samples long) on a short recording? No: all 84 recordings on each stream run 10,200–12,000 frames.
* The table's values and Figure 1's plotted values are the same quantity (`by_mouse.accuracy`).
* The `line_bound` build calls `build_line`, and `provenance._git` changes nothing that is re-derived elsewhere.
