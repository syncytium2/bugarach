# Role 11: argument order ("Start With the Problem")

**Artifact:** <repo>/docs/methods/one_page/methods_one_page.html. I read the HTML source, not the PDF render. For source checks I used <repo>/docs/adr/0010-tune-train-and-review-against-the-data-as-they-are.md.

## Arc applied
A methods reader follows data provenance, not a problem→fix arc. The arc I judged against is the order a replicator would follow: object and input → constants derived from the data → simulated data built from those constants → how the simulated data are scored → how each detector is tuned or trained against that score → how the detectors are compared → what the flow returns. It is the PI's requested order, with one change that has to be justified: the scoring rules must come before optimisation, because the optimisation is defined in terms of them. The one problem-first element I still require is a single clause saying what a "coordinated event" is before the input is described.

## Spine (one claim per titled paragraph)
1. **Input.** The flow reads exported per-ROI event onsets (half-rise time t50, 0.1 s grid) in fast and slow streams, plus a combined stream that is their labelled union without merging. It runs on 66 recordings in four groups, and every data-derived constant comes from baseline windows only.
2. **Participation floor.** For each window and stream, a call needs at least K co-active ROIs, where K is the smallest count whose chance crossings stay at or below 1 per hour under 1,000 rigid per-ROI shifts (J = 20 s). K is never below 3.
3. **Parameters for simulation.** Four quantities are measured from the data: timing spread (from the correlogram), quiet and busy background rates, the participation fraction, and the spacing between events (found without any detector, as count peaks at or above the floor).
4. **Simulated recordings.** Each recording has 32 ROIs and lasts 45 min. It plants the measured number of events at three participation levels, with gaps drawn from pooled data, on a quiet or busy background with decoys. There are two recordings with nothing planted, an ORX-spaced variant, and disjoint seed sets for selection, held-out confirmation and final scoring.
5. **Scoring.** Calls are matched one-to-one within 2.5 s and events under the floor are "don't care". Precision, recall and F1 are pooled and merges are counted. Every operating point must meet three budgets: empty-recording rate, elevated-rate stretch, and precision drop.
6. **CoactDetect.** A CFAR (constant-false-alarm-rate) z-test on the co-active count, with the floor applied and nearby windows merged. It is tuned by coordinate search from the shipped point, and a candidate is adopted only if its held-out gain has a 95% interval above zero, its best value is bracketed and it meets every budget.
7. **Chorus.** A permutation-invariant dilated convolutional network, plus a participation variant, trained on simulated recordings with events planted around the floor. The best of 5 seeds within CoactDetect's budget is kept. The paragraph's last sentence adds that every detector is compared with CoactDetect on fresh seeds as a paired F1 difference.
8. **Output.** Each call becomes onset, span and count. Every call is measured the same way whichever detector made it: core group, event time, width and amplitude (ROIs per second).

## Overall verdict
The order mostly works. The PI's sequence (onsets → combined → parameters → simulated data → optimisation/training → benchmark → output) is honoured, with two deviations:

- **Floor inserted before parameters (spine 2).** Justified by dependency, because spacing (3), scoring (5) and both detectors use it. The paper never says why it sits there, but it is self-evidently right.
- **Benchmark split in two.** Scoring rules (5) come before optimisation, which is necessary because optimisation uses budgets and held-out F1. The actual benchmark, the fresh-seed paired comparison, is buried as the last sentence of Chorus. This is the main order defect.

"Floor defined before use" passes. Budgets arrive before the detectors they constrain, which also passes. "Held-out", "budgets" and "bracketed" all point back to earlier definitions. The real problems are listed below.
