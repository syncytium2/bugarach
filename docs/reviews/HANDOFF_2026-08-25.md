# Murderboard run — HANDOFF.md (the root in-flight handoff, PR #305)

## What was at stake

This file is not a document that happens to sit at the root. It **is** the repo's
"something is in flight" signal — CLAUDE.md rests *"no handoff file on `main` == nothing
in flight"* on its presence, and `tools/session_briefing.sh` surfaces its first fourteen
lines at every session start. A handoff that is wrong is not a document defect; it is a
broken instrument, and `docs/handoffs/README.md` already prices that at four days.

It reached this review having **skipped the murderboard entirely** — CLAUDE.md names "a
human-facing handoff" in the trigger list — and carrying four defects found in PR review
before the process ever ran: a dangling ADR-0003 link, a stale open-PR list, a stale suite
count, and a stale todo count. Those were repaired first. The murderboard then found a
fifth, in the file's own headline.

**Role 4's finding: "`main` now carries nine references to ADR-0003."** It carried ten by
the time the review ran, and the tenth was added by [#309](https://github.com/syncytium2/bugarach/pull/309) —
this same session, writing about the problem. The set grows every time anyone documents
the decision, so the count was wrong on arrival and would be wrong again by morning. It now
**names the files** instead, per this repo's own writing convention: *name things, don't
index them*. Names survive; counts rot.

That is the fifth stale-status defect in a file whose central observation is that *"what
goes stale here is not facts but status."* The document now says so about itself.

## What would validate this

The claim is now machine-checkable, which it was not before.
`tests/test_handoff_is_honest.py` asserts that a root handoff **names** the PR it says is
in flight, and that at least one named PR is still open. Run against this file it resolves
**#298 → OPEN**; when #298 closes the test goes red and names what closed. That is the
retirement mechanism `docs/handoffs/README.md` was missing.

The third test in that module proves the guard can fire, on a synthetic all-closed state
map rather than by planting a `HANDOFF.md` at the root — forging that file, even for a
second, would lie to every other session on the machine.

Role 10 added the check unique to this artifact: with `HANDOFF.md` present the briefing
measures **8,428B against its 9,000B budget**. The handoff contributes a capped `head -14`,
so the file cannot grow the briefing past the ladder no matter how long it gets. Before
#306 this same file's alarm sat at byte 17,569 of a stream cut at 2,000.

## How it generalises

Every defect here and in the two reviews before it was a **status** defect — true when
written, false when read. Counts, PR lists, suite totals, "nine references". The
countermeasure that worked was never more care: it was moving the claim from prose to
something that runs. The briefing prints its own size; the handoff names a PR a test can
resolve. Anything in a durable document that a machine could check and doesn't is the next
one of these.
