## Checked and found correct (no finding)

- **Circular shift and block control:** called through `bugarach.surrogates`, with windows in frames and keys that include `TAG`. The block width is rounded the same way `_tiles` rounds it (`surrogates.py:268-273`).
- **Membership in CoactDetect episodes** (`measure_slow_comodulation.py:204-207`): checked against CoactDetect's own bin assignment, `floor((t - t0)/bw)` at `coact.py:114` with episode edges at `coact.py:259-260`. On 40 lab recordings, fast and slow, 6,990 onsets fall inside episodes and there are 0 disagreements.
- **Frame-rounded, re-zeroed times fed to CoactDetect:** these give episodes identical to raw `t50rise` on the absolute baseline span, in all 24 stream-recordings tested. The seed defaults to 20260706, the same as `detect_folder.RNG_SEED`.
- **Fast-stream settings:** match `bench.OPERATING_POINTS["coact"]`. `COACT_SLOW` matches the docstring at `coact.py:86-87`.
- **Baseline window:** comes from `surrogate_stats.recordings_from_slices`, which uses `assess_folder.generation_window` (`<worktree>/src/bugarach/assess_folder.py:80`). That is the canonical rule, with the analysis window winning inside the longest baseline region.
- **Start of the Dard et al. (Cossart) folder:** trimming to the first onset gives the same frames as `detectors.rate.recording_extent` (`<worktree>/src/bugarach/detectors/rate.py:94`) for all 59 recordings (difference 0 frames at both ends).
- **Rounding:** `int(round(sec/dt))` never disagrees with the halves-away rule in `ss.to_frames` for any frame interval in either folder. The lab uses 0.1 s; Dard et al. has 9 values between 0.0926 and 0.1190 s.
- **Duplicate onsets:** there are no same-frame duplicates within an ROI in any real stream (0 of 44,447 fast, 26,179 slow, 935,965 Dard et al.). So the counting raster's `np.add.at` and the binary rasters elsewhere agree.
- **Correlogram code:** no correlogram or FFT autocorrelation exists anywhere else in `src/` or `tools/`, and none of the new code's shared-modulation (OU) generator or count-variance code duplicates something already in the tree. `count_dispersion.burst_rows`/`fano` (`<worktree>/src/bugarach/count_dispersion.py:21-43`) is a different quantity: per ROI, including the partial last bin, with ddof 0.
- **Output folder and shared helpers:** both tools resolve their output folder with `paths.darkroom` and `unresolved_message`. The figure uses `detectors._shared.distinct_coact` for its lit-ROI counts. Its matplotlib `vlines` rasters are what `make_rigid_shift_controls_figure.py` and `make_tube_aggregate_figure.py` do too.
- **Seeds:** `ss.rng_of` and `ss.seed_of(...) & 0x7FFFFFFF` follow the same pattern as `tube_self_supervised.seed31`.
