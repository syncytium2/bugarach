# Role 7, reuse auditor: report for tools/make_replicate_report.py

**Summary.** The tool reuses most of what it should: `darkroom`/`unresolved_message`, `bench.make_recording` and `run_detector` for the raster, `diagnostic.lane_panel`/`raster_panel`/`legend_html`, and `make_diagnostic._render_png`. It reads the tuner's own fields for flags and budget compliance. The serious problem is one quantity it builds itself: the three-way split of false alarms (Figure 9, section 9 and the raster caption). That split reads `Score.distractor_hits` as "false alarms on a distractor". It is not that, and the built page already contains negative false-alarm counts as a result. The remaining findings are low severity: places where the tool re-implements code it could have called. I checked each against the run data or a re-run, and the numbers match today.

Sources I checked against:
- The tuner on the `replicate-run` branch (worktree `weekend-runs`). It is **not on main**: the report branch has no history for `tools/tune_learned_vs_coact.py`. So the tuner's helpers cannot be imported from the report's worktree, and that limits several of the fixes below.
- `git diff HEAD replicate-run -- src/` is empty for `bench.py`, `score.py`, `simulate.py` and `detectors/`. The raster is therefore the same recording and detector the run scored.
