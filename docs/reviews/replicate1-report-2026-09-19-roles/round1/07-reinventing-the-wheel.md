# Role 7, reuse auditor: round 1 report on `tools/make_replicate_report.py`

The tool mostly reads the tuner's own files and calls the project's own code. **The main problem is that it wrote a reader for the tuner's own over-budget flag and never used it.** In place of that flag it used a narrower test it worked out itself (does the selection file show every candidate refused?). The two disagree, and the one CoactDetect cell where they disagree is not marked on the page.

Before judging "should it import the tuner", note this: `tools/tune_learned_vs_coact.py` is **not on `main`**. It exists only on branch `replicate-run` (`git ls-tree main` gives nothing for it). So reading `results.json`/`meta.json` instead of importing `summarize`/`within`/`objective` is justified. The findings below are about the cases where the tool re-derives something the run's files already hold, or holds and ignores.

All paths below are absolute. "Report" means `%USERPROFILE%\bugarach\bugarach-worktrees\replicate-report\tools\make_replicate_report.py`. "Tuner" means `%USERPROFILE%\bugarach\bugarach-worktrees\weekend-runs\tools\tune_learned_vs_coact.py`.

## What this tool reuses correctly (checked, no finding)

- **Selection, over-budget and edge data:** `failed_training_signature` comes from the run's own flag. The edge flags' `'high'`/`'low'` values match what `choose_settings` writes (every detector is in `search` mode in both runs). `comparisons["gated"]["<net> - coact"]` is read, not recomputed. The declaration-difference assert and the disjoint-seed assert are both present.
- **Raster:** built through `bench.make_recording` (the tuner's `_planted` path), with `make_diagnostic._dt_for` and `_render_png`. The time axis comes from `lane_panel`/`raster_panel`, which apply `_time_axis_hook`, with one x-axis only on the bottom panel.
- **Output location:** darkroom by default via `paths.darkroom` and `unresolved_message`, plus `--also` (SAP006 shape). `figure_destination.py` is matplotlib-only, so it was rightly not used.
- **Pooling:** the tool does no pooling or F1 arithmetic of its own, so it does not bypass `bench.pool_scores`.
- **`table_learned_vs_coact.py`** reads `fair_bakeoff` runs, not this format, so it is not a reuse candidate. **`compare_bakeoff_runs.py`** is not either.
