# Murderboard run — README.md

## The problem: the front page described a tool two milestones behind

The README carried a section headed **"What is not built: a result you can take
away"**, which told every reader that there was still no `detections.csv` and that
"the detection path writes nothing." By the day of this review there were three
routes to a detections file — the browser page, `bugarach detect`, and the Panel
viewer's Save button — and the whole-folder route had just run this lab's 84-recording
export through all six detectors in 44 seconds.

That is an expensive kind of wrong. FOUNDATIONS §8 makes this repo a portfolio
artifact: its README is read by people deciding whether to take its author seriously,
and a false *"this is not built"* costs more than a bug, because nobody files it. The
same claim had spread to three sibling documents.

**The review did not stop at inverting those sentences.** Eleven roles ran against the
repaired text, and the interesting result is that most of what they found was not the
original lie — it was the *repair* overclaiming in the other direction, plus a layer
of claims that had quietly gone stale underneath. Three examples, all caught here and
all now corrected:

- The repaired README said `bugarach detect` **"refuses a folder that states no
  interval."** It does not. It refuses one *recording* at a time, records the refusal
  in `run.json`, writes an empty `detections.csv`, and **exits 0** — so a script
  gating on exit status is told the run succeeded and found no coordinated events.
  `bugarach check` exits 1 on the same folder. The false claim was introduced by the
  fix, and the same sentence had been copied into `workflow_plan.md`.
- The bake-off table called the top three detectors **a tie**, on F1 — a metric that
  by design excludes firings in the no-event probe block. On the column F1 cannot see,
  the learned model fires **15.8** times a fold against CoactDetect's **1.2**. The
  document explained that exclusion fifty lines earlier and then ranked nine detectors
  without it. The table now carries a `probe firings` column.
- **"A different choice halves the event rate"** was a claim this project had already
  measured, retracted and swept from six places. It had survived in the README alone,
  and the README was the most-read of the seven. The real figure is roughly a quarter.

## What was found and fixed

Fifty-three edits landed across the four documents. The ones that changed what a
reader would believe:

| what it said | what is true |
|---|---|
| no `detections.csv`; "the detection path writes nothing" | three routes write it; six real rows of one are now shown rather than described |
| "one row per detected coordinated event" | one row per **call** — six detectors write up to six rows for one moment, and nothing reconciles them |
| `detect` "refuses a folder" with no frame interval | refuses per recording, records it, **exits 0** — run `check` first |
| the top three "are a tie" | tied on F1, and not tied on the trap the F1 cannot see |
| a different K "halves" the event rate | quarters it — a retracted claim that had crept back |
| ports matched "on committed fixtures **and on a real slice locally**" | no real-slice parity test exists; the committed fixtures are the whole checkable claim |
| "a bench with two refusals" | four; the promiscuity gate and the degenerate-sweep refusal are both recent |
| probe firings "cannot cost a detector anything" | they no longer cost a *score* but now cost an *operating point* |
| "1,126 tests … 1,119 pass" | 1,143 collected, 1,136 pass, 7 skip |
| "the two earliest ports" spell `locs`/`widths` | the first port and the last, and the reason is parity, not port order |
| all six take "whichever of the two detection modes" | five do; CICADA has one mode, and `width_def` is `NA` for three |
| `workflow_plan.md`: "`events.csv` is the only one that must exist" | `<slice_id>.csv`, one per recording — the contract changed at revision 2 |
| `webapp_completion_plan.md`: "no `Blob(`, no download, anywhere" + five unmerged PRs | the page writes files; every PR merged |
| `lanes.md`: scoring "not yet spliced", "no download button yet" | both done; the queue is empty |

Two code defects surfaced that prose cannot fix, and both are filed rather than
papered over: `tools/make_diagnostic.py` **fails soft into an empty figure and exits
0** because the viewer's compute function gained a required argument, and the
committed diagnostic figures are one CICADA recalibration behind (85/28 probe firings
on the page against 35/29 in the tree today). The README now says so beside the
figure.

## What would validate this, and how it generalizes

The check that matters is the one the murderboard's own roster gate performs: every
role accounted for, none silently dropped. Beyond that, three of the fixes are
mechanically re-checkable and should be re-run whenever this page is touched — the
test count, the bake-off table against `docs/learned/bakeoff.json`, and every relative
link. The claims that are *not* mechanically checkable are the ones this review had to
buy with agent time, and they are the ones that rot: a number quoted from a docstring
whose regime has been retired, a "cannot" that a test does not actually buy, a figure
whose caption outlived its calibration.

The generalizable finding is about **where staleness hides**. Not one of the four
false claims this lane was chartered to fix was a typo or a careless sentence. Each
was true when written. What made them dangerous is that they were *specific* — a
number, a filename, a "there is no X" — and specificity reads as verification. The
three worst findings in this run all have that shape.

### The blind verify pass, and why it mattered

The process file insists the repaired artifact is re-reviewed **blind first** — a pass
that has not seen the finding list, because a list-driven follow-up only confirms the
list. That is exactly what happened here, and it paid for itself three times over.

**It caught a defect the repair introduced.** The six sample rows of `detections.csv`
were captioned as coming from `simulate_coordination(seed=1)` at the bench operating
points. They did not: they came from a CSV round-trip through a hand-built export
folder, and three of the six differed. Worse, the paragraph explaining them was built
on the wrong numbers — it argued that binned SCE's row "stops before the event it
found", which is true of the printed figures and **false** of the real ones, where the
bin's interval contains the event. Two independent agents and a third check agreed on
the reproducible values; the table and the paragraph were both replaced.

**It caught two claims the tree invalidated mid-review.** The `dt`-at-load work landed
while the roles were running, which made the frame-interval paragraph wrong in the
opposite direction from the one it had been wrong in that morning: rate+context and
CICADA now **refuse** rather than warn or assume, and only SPIKE-synch still guesses.
The same landing broke both printed Python snippets, which had been correct an hour
earlier. And the todo the paragraph cited had closed.

**It found a mitigation that does not mitigate.** The repaired text told readers to run
`bugarach check` first, since it exits 1 where `detect` exits 0. It does — for a
`slices.csv` whose interval is missing, blank or `NA`. For a folder with **no
`slices.csv` at all**, which is the shape a stranger is likeliest to produce, `check`
also exits 0. The advice was replaced with the one thing that does work.

### Adjudication: what was deliberately not done

Three roles proposed work this lane declined, and the reasons matter more than the
refusals.

**The restructure (role 11) was not performed.** Role 11 makes a good case that the
README should open with the problem and its cost, lead with the diagnostic figure
rather than the GUI screenshot, and move the warrant above the install wall. That is a
rewrite of a document this lane was chartered to make *honest*, not to re-argue, and
it would have made every other role's verification stale. Recorded as the strongest
open recommendation for whoever takes the README next; role 11's minimum-viable
version is three moves.

**Most figure work was not performed.** Roles 8 and 9 want the glyph legend baked into
the hero PNG, the bake-off's fold whiskers redrawn as dots so they cannot be misread as
error bars, and a four-box schematic for the per-lab loop. All three need the renderer,
and the renderer is broken — which is itself now filed.

**Two defects in files this lane does not own are flagged, not fixed:** the export
contract's output table omits `width_def` and never mentions `run.json`, and
`bench.py`'s module docstring still says "two things this module refuses to do" where
the code has four. Both are named in the todos below.
