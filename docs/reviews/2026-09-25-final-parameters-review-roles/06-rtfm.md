# Role 6 — RTFM: methods / domain review of the final-parameters report and its code

**Grounded in:** ADR-0008, ADR-0009, `src/bugarach/event_floor.py`; the branch diff (`git diff main...HEAD`) of `bench.py`, `bench_slow.py`, `bench_combined.py`, `score.py`; `tools/search_all_settings.py` (`make_admissible`, `bracketing`, `coordinate_rounds`, `held_out`, `warm_floors`), `tools/score_bench_candidates.py`, `tools/score_cross_stream.py` (`versions_from`, `job`), `tools/make_final_parameters_report.py`; and the darkroom records (every `search.json`, both `candidates.json`, `selection_budgets.json`, `cross_stream.json`, `bench_floor.json`). Code was run in the tune-bench-comparison venv with `PYTHONPATH=<worktree>\src`. No papers were needed: the method is defined in-repo by the ADRs.

**Holds up (verified yes):**
- **The floor code matches ADR-0008.** `event_floor.py` computes `max(3, chance)` with `FA_PER_HOUR` = 1, `J_SEC` = 20, `WINDOW_SEC` = 2 and `MIN_DRAWS` = 1000; a per-ROI rigid shift with *J* trimmed from both ends; calls counted as runs of positions ≥ *K*; and a correct per-half normalisation `(draws+1-h)//2`. `recording_floor` builds each floor from the recording's own events, stretch included, as ADR-0009 decision 1 requires.
- **Don't-care scoring matches ADR-0009 decision 2.** An event with `n_part < floor` leaves `n_planted`, its one-to-one matched call leaves `n_detected`, and the counts are reported by level.
- **The floor is applied uniformly.** `floored_params` sets `min_rois`, or SPIKE-synch's `min_n`, from the scored recording's own floor on every bench; it refuses a caller override; and `min_rois` and `min_n` are gone from `FULL_GRIDS`.
- **The 3 × 3 is scored as the report says.** Each version runs through the tuned-on bench's `run_detector` on the scored-on bench's recording, with the floor taken from that recording. The records confirm 38/38 diagonal cells reproduce and 114/114 cells ran.
- **`selection_budgets.json` agrees with the gate.** In all 32 rows the limits equal the bench constants, and every check boolean equals `make_admissible`'s logic applied to the recorded values (probe on both backgrounds, empty recording, elevated-rate outside its stretch on quiet only, precision swing, crowded against its reference). The four shipped points the report calls out of budget are exactly the four with `admissible: false`.
- **The held-out probe conversion is right.** `probe_*_per_hour / 60` inverts the search's `60 * probe_per_min`.
- **The bootstrap is as described:** 400 resamples of held-out seeds 49–96, paired (the same resample index for proposal and shipped), pooled F1, the mean over the two backgrounds.
