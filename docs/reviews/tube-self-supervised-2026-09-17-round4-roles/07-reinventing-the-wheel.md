## Checks that matched

- **Supervised arm against the bake-off:** `scores.oracle_bakeoff_rule.f1` in `training/results.jsonl` equals the bake-off per-fold F1 in `bakeoff_seed*/bakeoff*.json` for **60 of 60** fold-seed fits. The parameters in `tube_self_supervised.py:593` and `tube_aggregate_leak.py:303` match `fair_bakeoff.py:293–295`, with lr read from `fb.LR`.
- **Rigid shift's edge rule:** Elephant's `dither_spike_train(edges=True)` keeps onsets in [t_start, t_stop); after `_back`'s floor that is exactly `rigid_frames`' 0 ≤ k < L. `look_rigid_shift_controls.shared_shift` (lines 69–84) uses the same construction as `rigid_frames(shared=True)`: duplicated, but consistent.
- **Truth-reading threshold:** it calls `pick_threshold` itself (`train.py:244`) with `grid=quantile_grid`, `logits=True`, `report=` and `fold_maker`'s `n_val`, so it is not a re-derivation. `MERGE_GAP = 20` equals the `decode` and `pick_threshold` defaults.
- **Held-out scoring:** `encode`, then `decode`, `score_stream` and `pool_scores(regime="heldout")`, the same path as the bake-off's `Trained.predict`.
- **ROI order:** `tube` and `line` pool with a mean or sum over ROIs, so the unsorted rows from `raster_of` don't matter for the five models run.
- **Per-ROI leak test:** every surrogate goes through `sg.generate` (rigid shift, uniform dither, circular shift). It uses `sd.pair_features`, `sd.mouse_folds` and `lr.refit_bootstrap`. The aggregate leak test uses the same bootstrap.
- **Modulation twins:** one implementation (`ts.modulated`) serves the aggregate leak test, the paired checks and the twin check.
- **CoactDetect and LoCo** on real recordings go through `bugarach.detect_folder.detect_slice`.
- **`tools/figure_destination.py`** resolves through `bugarach.paths.darkroom(create=True)` and `unresolved_message`, with `--also` for the repo copy.
- **Summary statistics:** sign-test p values (1.00, 0.63, 0.13) are consistent with 2, 3 and 4 positive folds of 4. The edge-of-grid bounds (1e-4 and 0.9999) match `pick_threshold`'s default grid (`train.py:295–298`). Nothing in `src/` or `tools/` already implements the Nadeau–Bengio correction, so there was nothing to reuse.
- **Figure 2 panels A and B:** the maker reads raw results through `--run`, not `summary.json`, but uses the same `by_mouse` accuracy as the summary's `leak_digest`. Its numbers match the table, though README line 672 says every figure is drawn from `summary.json`.
