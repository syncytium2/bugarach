## ⚠ How this run differed from the process, and what that costs

The eleven roles were spawned as parallel subagents as the skill requires. **All
eleven died within a minute on the same API spend limit**, four of them after
doing real work. The process's stated fallback for a small deliverable — a
single-pass self-review that still walks every role's checklist — was therefore
run by the main thread instead, which is a weaker instrument in two specific ways
a reader of this record should hold against it:

1. **The reviewer is the author.** Every judgement role (Reviewer 2, You Lost Me,
   Start With the Problem) was run with the same context that produced the draft,
   which is exactly the failure direction the process warns about: less scrutiny
   of what the author was already comfortable with.
2. **The verify pass was not blind.** It was a fresh end-to-end read by the thread
   that made the fixes. It caught three regressions the fixes introduced, so it
   was not worthless — but a reviewer who had never seen the finding list would be
   a real check, and this was not that.

Four roles returned partial results before dying and those are folded in, marked
*(partial, agent)*: Prove It, DOI or Die, RTFM, Ship It.

**Recommendation:** re-run the fan-out against this file when the limit resets.
The defects below were found by mechanical verification — running the code,
recomputing the numbers, opening the figures — and that half of the review is
solid. The adversarial half is the half that was weakened.

## Correction — 2026-08-18: finding 2 was wrong, and the fix it produced was worse

**Finding 2 above ("all six return the same output contract" is false) is
retracted.** Tony caught it: the six *do* share an output contract, and it is
named in `detectors/__init__.py` and specified in interface2's
`detector_output_spec.md` — a statistic trace plus the events found in it as
onset and width, in either detection mode. The review reached that verdict from
two sampled dataclasses (`RateDetection.locs` vs `LocoStream.onset_sec`) without
reading the module docstring that states the contract or the three consumers that
depend on it, and the "fix" then deleted a true claim and replaced it with a
narrower and less useful one.

What the review missed, all of it checkable in a minute:

- `detectors/__init__.py` states the contract in its own docstring.
- `bench.run_detector` absorbs the two call shapes so callers work in detector
  names rather than signatures.
- `score.score_stream` absorbs the two field spellings, with `_ONSET_FIELDS`
  naming both, and its docstring says which detectors use which.
- `ui/app.py`'s `_compute` returns the same four-part shape — trace, events,
  widths, threshold — for every one of the six.

**The replacement claim was verified as hard as the one it replaces**, per this
process's own correction rule, and that caught a second defect before it shipped:
`bench.run_detector` is **bench-scoped**. It hardcodes `STREAM = "events"`, so on
a two-stream store it raises `KeyError: 'events'` rather than running. Advertising
it as the general entry point would have handed a reader a crash. The corrected
passage therefore names it as what it is — the way the bench and the generator's
single-stream recordings run all six by name — and points at the viewer's own
dispatch for stores with several streams. The scoring loop now in the README was
executed verbatim before it was written down.

**Why the original review produced it.** This is the run whose fan-out died on a
spend limit, leaving the roles to be walked single-pass by the author. Reuse
auditor ("Reinventing the Wheel") is the role that would have asked whether the
project already had one path for all six, and it was the thinnest of the eleven
when run by the same context that wrote the draft. The residual flag at the top of
this record said the adversarial half was the weak half; this is what that cost.
