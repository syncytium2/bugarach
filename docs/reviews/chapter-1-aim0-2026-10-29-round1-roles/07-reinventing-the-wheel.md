# Role 7: Reuse auditor ("Reinventing the Wheel"). Chapter 1, Aim 0

**Verdict.** I would not sign off yet. Two things block it:
- **The jitter claim.** The chapter's headline jitter claim was never tested against a jitter tool the repository already has.
- **The real-gap numbers.** Section 1.5.4's real-gap numbers come from three different implementations of the same check. The chapter's own reproduction command does not print the values it quotes.

Most of the analysis code reuses production code correctly. That is confirmed in the next section, so the findings below are the exceptions.

## What reuses production code correctly (checked; no change needed)

- **Chance-cluster prediction.** `theory.chance_clusters_per_min` (theory.py L241–261) reads the assessor's bin width and `merge_bins` from `assess_coactivity`'s signature. It reproduces `_clusters`' rule exactly: in `src/bugarach/assess.py` L288–301, bins merge when `fire[q]-fire[q-1] <= merge_bins`, so a cluster starts at rate q(1−q)². The ±1.5 s gather (`wm_factor` × bin, L378/L513) cannot drop a single-bin cluster.
- **Predictions go through the shipped estimator.** `predict_solve` calls `tools/measure_coordination_rates.solve`.
- **The surrogate model matches the tool.** `event_train._coefficients` models the tool's surrogate (`mcr.shifted`: a permutation × spacing) and reads `mcr.SURR_SPACING` rather than copying the value. The uniform-phase assumption matches `population_cumulants`, which averages over two window phases.
- **Aim 1a uses the shipped tools throughout.** `aim1_one_source.py` uses `simulate_coordination`, `mcr.measure`/`_frames`/`truth` and `assess_coactivity`. Its k levels of 5, 10 and 20 match the generator's `matlab_round(f·33)`.
- **The membership study uses the shipped assembly test.** `membership_limit.py` calls `bugarach.assembly.stat_dispersion`, both nulls and `AssemblyResult.verdict()`.
- **The separation study cross-checks against the shipped tools.** `separation/assessor_split/split.py` uses `assess._coact_count`, `_clusters` and `detectors.count.count_detect`, and checks itself against the shipped `assess_coactivity`. Its hard-coded settings match production today: 1 s and 2 s bins, merges of 2 bins and 3 s, `wm` 1.5. They also match the count detector's operating point in `bench.py` L866–869 (`bin_sec=2.0, k_offset=0, merge_gap_sec=3.0`).
