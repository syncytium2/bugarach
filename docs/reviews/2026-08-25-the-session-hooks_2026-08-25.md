# Murderboard run — docs/handoffs/2026-08-25-the-session-hooks.md

## What was at stake

The artifact is a handoff about the session hooks, and its central claim is that a
briefing can pass every test it has and still reach nobody. A handoff making that claim
had better not itself carry numbers that were true once and re-quoted later — which is
exactly what the review found, four times, before anything else.

**Role 1 was the whole review.** Six of the eight figures in the first draft were
re-measurements taken in a different worktree at a different moment than the incident they
described, and three of them were wrong by the time they were written down:

| claim in draft | actual | why it drifted |
|---|---|---|
| open-todo dump `9,658B, 55%` | **9,838B, 56%** | re-measured in a tree with a different todo set; the real figure is in the spilled output |
| `17,439B → 8,016B, or 8,768B` | **→ 8,068B, or 8,820B** | measured before the board grew two blocks |
| guard substring `263` | **267** | same — the board grows while you write about it |
| `2,600-line board` | **3,006** | estimated, not counted |
| two hooks total `14.8KB` | **~14KB** (8,068 + 6,282) | added a fresh number to a session-observed one |

The fix was not just corrected digits. The document now says **which** figures are
re-measurements and which is the one observed number (`17,568B`, what the harness reported
when it refused the injection), and says that briefing size tracks the board, the todos and
the handoff — so it moves, which is the reason the fix is a run-time canary rather than an
asserted constant. A handoff that quoted a fixed size would have been wrong within a day.

Role 4 caught one overstatement of substance: the draft said `session_briefing.sh` is *"the
only thing in the tree that reads HANDOFF.md."* Seven files mention it; one acts on it. The
claim now distinguishes code from prose, which is what makes it load-bearing. Role 4 also
narrowed the board-guard finding — the guard is not universally broken, it cannot fail *in
the primary checkout* and for any worktree whose name is a substring of the board.

Role 10 caught the review's own accident: a `perl -0pi` correction pass double-encoded the
file, turning 25 em-dashes into mojibake and introducing NEL line terminators. The artifact
was rewritten through the file tools rather than the shell. This repo already has a
`PreToolUse` hook forbidding source writes through heredocs for exactly this reason; the
lesson generalises to in-place shell rewriting of prose, and that is worth a rule.

## What would validate this

The corrected document's reproduce block was run against merged `main`, not against the
branch it was written on: `session_briefing.sh` reports 8,068B, `--selftest` passes every
rung, and `BUGARACH_BRIEFING_BUDGET_BYTES=1` produces the degraded form with its alarms
intact. If those three commands stop agreeing with the page, the page is stale.

## How it generalises

Every defect here was a **status** defect, not a fact defect — a number true when measured
and false when read. That is the same class PR #305's own body names as the week's pattern,
and the same class this handoff's subject belongs to: a briefing whose tests asserted what
it printed rather than what arrived. The countermeasure in all three cases is the same one:
measure at the moment of use and print the number, rather than recording it once.
