A learned detector does not work yet. The measurement around it does.

The target, and why it changes the design

The goal is not one detector that beats the six. It is a tool a lab can point at its own recordings: measure my data → parameterize the generator → train → detect. What ships is the loop, not a checkpoint.

That makes “mass” mean training cost on a laptop, not just parameter count — and it rules out anything needing a GPU, a tuned learning rate, or a fixed ROI count. It also mostly dissolves the project’s standing objection that our synthetic data may not match anyone else’s reality: if each lab generates from its own measurements, the domain gap is theirs to close and this hands them the means.

Steps 1–2: measuring coordination without a detector

Three of the generator’s knobs are coordination properties — how often events happen, how many cells they recruit, how tightly. Measuring those with the six detectors would make every simulated recording a restatement of whichever detector measured it, and training on that closes the circle.

The assessor avoids it. It has no operating point: it compares observed coactivity against a null built by circularly shifting each ROI within the window, which holds every cell’s own rate and burstiness and destroys only cross-cell timing. What survives is coordination the slice’s rate cannot explain.

It was MATLAB-only, which broke the loop at its first step — the one thing this project exists to remove. It is now Python, at the same 1e‑9 bar as the six ports.

Two biases are worth carrying forward. Participants come out high (7 against a planted 5.9 at K=4) because the measure only sees groups that already cleared K — a selection effect, not noise. Tightness comes out ~9% loose at every K, because the gather window admits onsets that were not participants. That second one errs toward a harder simulation than reality, which is the safe direction.

Step 3: why this network

The architecture was not chosen from a menu. Four constraints each removed most of the design space, and what is left is close to forced.

Cell identity carries no information, so row order must be canonical

(The figures label these ROIs — the regions of interest a segmentation found. Same thing.) Cell #3 in one recording has nothing to do with cell #3 in the next, and recordings differ in how many cells they have. A model reading the raster as an image can learn “rows 3, 7 and 19 together” — a fact about one segmentation that cannot transfer and cannot even run on the next recording.

Rows are therefore sorted by firing frequency, busiest first — which is how a person reads a raster anyway. That turns row position from a meaningless label into a real coordinate: how active is this cell relative to the others.

This broke on its first test, and the test is why it is now right. Sorting by rate leaves ties, and the first implementation broke them by original row number — exactly the arbitrary label the sort exists to remove. Shuffling the input changed the encoding. Ties are now broken by each cell’s own firing pattern, so the encoding is a function of the data alone.

An event is some number of samples wide, never some number of seconds

At our imaging rate a coordinated event spans about four samples. The same biological event recorded at 30 Hz spans eleven. A model trained on seconds-shaped windows has learned our microscope, and nothing on our bench could show it, because every bench recording shares one imaging rate.

So nothing inside the model knows what a second is. Seconds appear at exactly two boundaries: the sampling interval is required when data is loaded, and detections are converted back to seconds at the end so they can be scored the same way as the six.

The width of an event is learned, not supplied

An earlier draft handed the model a bank of fixed time-scales centred on the width we had measured. That is the answer written into the input. It was removed: the model gets activity at full resolution and its filters have to find their own scale. Its receptive field spans about 2,000 samples so it can judge activity against its own local background rather than being told what that background is.

One cell, one vote — and this is what shapes the network

Coordination means distinct cells firing together. Every one of the six detectors enforces that. Collapse the cells into a single trace before smoothing over time and it is destroyed: one busy cell firing repeatedly becomes indistinguishable from several cells firing together, which is precisely the false coordination the hand-written detectors reject by rule.

Sorting by rate makes that worse, not better, because it puts every busiest cell in the same place. So the cell axis has to survive the temporal filter, and each cell’s contribution is capped before anything is pooled.

The cap is where “one cell, one vote” lives, and it is why the filter has to run once per cell rather than once per recording.

The cap is soft, and that is an unpaid debt. An exact “did this cell fire anywhere in this window” needs a fixed window, which is the assumption the design refuses to make. A smooth cap lets the model choose its own window and pays with approximate distinctness. Nothing has yet probed what that approximation costs.

A second model, trace, is registered as the control: it pools the cells immediately and gives distinctness up. If it ever matches the careful one, the machinery is not earning its compute — which is worth knowing either way.

What is ruled out

Four candidate explanations were tested and eliminated, so nobody re-derives them:

  • Not a broken model. Given a single window containing an event, it fits — reaching 0.75 confidence at the event and dropping its loss by half.
  • Not the encoding. The row-order bug above is fixed and pinned by a test.
  • Not only sparsity. Events occupy 0.5% of frames. Drawing half the training windows around an event changed the failure’s shape, not its outcome.
  • Not the two models being secretly identical. An earlier run had them producing byte-identical losses. They now differ in detections and threshold.

What is left is that a single window trains while the full task does not, which points at variance between batches rather than an inability to represent the target.

What I would do next

In order, and the first is a diagnostic rather than a fix — because three of the four suspects below are only worth testing if the answer comes back one way.

  1. Train on the old, easy generator settings. Before the measured values landed, every detector scored 0.9–1.0 on this bench. If the model learns there and not here, the pipeline is sound and the measured regime is simply hard — which is itself a result worth having. If it fails there too, the training loop is wrong and every tuning suspect below is premature.
  2. Cap the positive class weight. At 0.5% positives it currently sits near 200, so a batch’s loss is decided by how many event frames its three windows happened to contain. This is the cheapest single test and the most likely cause.
  3. Raise the batch size. Directly attacks the same variance.
  4. Consider a wider training target — an event footprint is about eight frames against a 2,000-sample receptive field. With one condition: the label itself must not move. An event is defined by what the generator planted, and a tolerance band used for the loss is a different object from the label. If one is added it must stay out of scoring and be stated.
If it needs far more training than this, that is a finding, not a knob. “Lightweight and trainable on user simulations” would then be in tension with this task at this event rate, and the target would need revisiting rather than the hyperparameters.

Two things I would like decided

Is a per-lab loop still the right shape given that the assessment has a judgement call in it? K changes the derived event frequency roughly tenfold across its scan, and a lab has to pick one. There is no review surface for that yet, and it is filed as needing one.

Does the generator revision land first? It is in flight, and it moves the distribution this whole loop is fitted to. Training a model now means training on a distribution that is about to change.
